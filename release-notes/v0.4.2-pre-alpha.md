## 🐞 Fixed in 0.4.2
- **iPhone: model downloads stopped with "bad URL"** right after Hugging Face handed the download to its download server (`us.aws.cdn.hf.co`). Downloads on the iPhone were rebuilt:
  - **Two steps.** The app first asks Hugging Face where the file is. Then it downloads from that address directly.
  - **Token stays with Hugging Face.** Your sign-in is only sent to Hugging Face, never to the download server. The download server's address is already signed.
  - **Downloads in the background.** iOS keeps a download going when you switch apps or lock the phone, and saves straight to storage.
  - **Picks up where it stopped.** If a download breaks or you stop it, tapping **Download** again continues from there.
  - **Checked before it's kept.** A model is only kept if it has exactly the number of bytes Hugging Face lists and is a real GGUF model file.
  - **Fallback.** If the background download can't start, the app tries once more as a normal download.
- **Fresh model list.** The list saved by 0.4.1 is thrown away, so the newer ranking rules apply straight away.
- **Honest progress.** Download progress shows only the bytes actually saved. "1 MB of 1.2 GB" no longer appears when nothing was downloaded.

## 🔍 Better logging (Settings → Activity log)
For each download, the log now shows:
- Hugging Face's answer.
- The full download address it gave. The secret signature values are hidden.
- The download server's answer.
- If something fails: the exact iOS error code, the address it failed on, and the server's own error message.
- At the end: the saved file's exact size.
